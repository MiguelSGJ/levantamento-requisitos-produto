# Política de segurança

A skill contém prompts e exemplos, não um servidor. Ainda assim, mudanças
podem produzir comportamentos perigosos, divulgar dados ou incentivar
decisões não autorizadas.

## Como reportar

**Não abra issue pública** contendo credenciais, dados pessoais, documentos
internos, identificadores de usuários, informações de terceiros ou detalhes
de exploração que exponham outras pessoas.

Se o repositório tiver habilitado **Private vulnerability reporting**, use a
guia **Security → Advisories → Report a vulnerability**. Caso contrário,
solicite aos mantenedores um canal privado antes de compartilhar detalhes.
Não envie conteúdo confidencial até que o canal tenha sido acordado.

## Escopo

Exemplos de problemas: prompt que autoriza acesso ou exclusão sem decisão
explícita; script que apaga instalação anterior; vazamento de tokens;
dependência maliciosa; links enganosos na documentação.

Não há prazo de correção garantido nesta fase. Evite compartilhar segredos
em issues e pull requests.
